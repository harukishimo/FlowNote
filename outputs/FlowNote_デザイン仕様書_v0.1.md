# FlowNote デザイン仕様書

> メモ入力・アクティビティ図・ポンチ絵出力の画面／操作仕様

- **文書ID:** FN-DS-001

- **版:** v0.1

- **状態:** 要件整理版 / Draft

- **作成日:** 2026-08-12

- **対象:** FlowNote MVP

---

## 1. 文書の目的

本書は、FlowNote MVPの情報設計、画面構成、キーボード操作、Markdown入力、状態表示、ポンチ絵の出力・保存、レスポンシブ対応およびアクセシビリティを定義する。

> **デザイン上の最重要原則**  ユーザーが『入力』『図生成』『HTML出力』『保存』の違いを迷わないこと。特に、出力は保存ではなく、保存は明示操作だけで発生する。

## 2. デザイン原則

| 原則 | 適用内容 |
| --- | --- |
| Writing first | 第一の主役はメモ入力。エディタを常に読み書きしやすい面積とする。 |
| Diagram as evidence | 図は文章の解釈結果として表示し、曖昧箇所を隠さない。 |
| Explicit persistence | 保存される操作には『保存』という語と状態変化を必ず表示する。 |
| Immediate feedback | Markdown、インデント、生成、保存の結果を操作直後に画面へ反映する。 |
| Calm business tool | 落ち着いた紙・ノート調で、長時間の業務利用でも視覚疲労を抑える。 |
| Keyboard native | 主要な編集操作をキーボードで完結できる。 |

## 3. 情報アーキテクチャ

```text
FlowNote
  ├─ ログイン
  │    └─ 共有パスワード入力
  └─ 認証済み領域
       ├─ メモ一覧
       │    ├─ 新規メモ
       │    ├─ 最近のメモ
       │    └─ 検索
       └─ メモ詳細
            ├─ メモエディタ
            ├─ アクティビティ図プレビュー
            └─ HTML出力
                 ├─ ポンチ絵プレビュー（未保存）
                 ├─ 出力設定
                 ├─ HTMLダウンロード（保存なし）
                 └─ ポンチ絵を保存（明示保存）
```

## 4. ログイン画面

### 4.1 画面構成

| 領域 | 仕様 |
| --- | --- |
| ページ | FlowNoteのロゴ、短い説明、中央のログインカード。メモ内容や一覧は表示しない |
| ラベル | 「パスワード」。placeholderだけに依存せず、常時表示ラベルを付ける |
| 入力 | `type=password`、autocomplete=`current-password`、パスワード表示／非表示ボタンを付ける |
| 主操作 | 「ログイン」ボタン。送信中は無効化し、「確認しています…」と表示する |
| Enter | パスワード入力中のEnterはログインを1回だけ実行する。メモエディタのEnter仕様とは画面が異なる |
| エラー | 「パスワードを確認してください」。正誤判定以外の内部情報やハッシュ形式を表示しない |
| 試行制限 | 「しばらく時間をおいて、もう一度お試しください」。残り試行回数や判定理由は表示しない |
| 設定不備 | 「現在ログインできません。管理者に連絡してください」。秘密情報を表示しない |

### 4.2 認証後の振る舞い

- ログイン成功後は、最初に要求した安全なアプリ内URL、またはメモ一覧へ遷移する。外部URLへのリダイレクトは許可しない。
- 認証済みでログイン画面を開いた場合はメモ一覧へ遷移する。
- ヘッダーのユーザーメニューへ「ログアウト」を置く。未保存変更がある場合は、通常の未保存離脱確認を先に行う。
- セッション期限切れ時はログイン画面へ戻し、保存していない入力がある場合は可能な範囲で復旧用ローカル下書きを保持する。

## 5. メモ画面

### 5.1 デスクトップ構成

| 領域 | 内容 | 幅・配置の目安 |
| --- | --- | --- |
| サイドバー | 新規作成、メモ一覧、検索 | 220-260px、左固定 |
| ヘッダー | 保存状態、HTML出力、ログアウト | 高さ56-64px、上部固定 |
| 文書ヘッダー | タイトル、説明、メタ情報 | 本文領域上部 |
| メモエディタ | Markdown対応の入力面、文字数、操作ヒント | 全体の40-46% |
| 図プレビュー | アクティビティ図、ズーム、警告 | 全体の54-60% |

### 5.2 エディタの基本状態

| 状態 | 表示 |
| --- | --- |
| 空 | 入力例と『Enterで改行 / Cmd + Enterで図を生成』をプレースホルダー表示 |
| 編集中・未保存 | ヘッダーに未保存ドットと『未保存』。保存ボタンを有効化 |
| 保存済み | 緑の小さなステータスと『保存済み』、最終保存時刻 |
| 図生成中 | 生成ボタン内に進捗、図領域には前回結果を薄く保持 |
| 生成失敗 | 入力を保持し、原因と再試行ボタンを図領域へ表示 |
| 曖昧箇所あり | 図下部に警告バー。該当ノードと元文章を関連表示 |

## 6. キーボード操作仕様

| 操作 | 結果 | 補足 |
| --- | --- | --- |
| Enter | 改行または現在ブロックと同種の次ブロックを作成 | 保存・図生成・送信は行わない |
| Shift + Enter | ソフト改行 | 同一段落内の改行が必要な場合 |
| Cmd + Enter | 図生成 | macOS。IME変換中は実行しない |
| Ctrl + Enter | 図生成 | Windows/Linux互換 |
| Tab | 1段インデント | 複数行選択時は全行。フォーカスを外へ移動しない |
| Shift + Tab | 1段アウトデント | 0段では変更なし |
| Cmd/Ctrl + S | メモ保存 | ブラウザのページ保存を抑止してアプリ保存を実行 |
| Cmd/Ctrl + Z | 直前操作を元に戻す | Markdown即時変換も1操作としてUndo可能 |
| Escape | 開いている候補、ポップオーバー、出力画面を閉じる | 未保存出力は確認ダイアログを表示 |

> **Tabとアクセシビリティ**  エディタ内ではTabをインデントへ使うため、ツールバーには『インデント』『アウトデント』ボタンも置く。Tabキーで次のUIへ移動したい利用者向けに、エディタを抜ける代替操作をヘルプへ明記する。

## 7. Markdown即時反映

### 7.1 振る舞い

1. ユーザーが行頭または本文にMarkdownショートカットを入力する。

1. 確定条件となるスペース、閉じ記号、またはEnterが入力される。

1. 入力ルールが一致した場合、記号を視覚的な書式へ即時変換する。

1. カーソル位置を自然な編集位置へ移し、入力を継続できるようにする。

1. Undoを1回実行すると変換前のMarkdown記号を含む状態へ戻る。

### 7.2 対応コマンド

| Markdown | 表示 | 確定タイミング |
| --- | --- | --- |
| # / ## / ### + Space | 見出し1 / 2 / 3 | Space |
| - / * + Space | 箇条書き | Space |
| 1. + Space | 番号付きリスト | Space |
| > + Space | 引用ブロック | Space |
| ``` | コードブロック | 3文字目 |
| **文字** | 太字 | 閉じ** |
| *文字* または _文字_ | 斜体 | 閉じ記号 |
| ~~文字~~ | 取り消し線 | 閉じ~~ |
| `文字` | インラインコード | 閉じ` |
| [表示](URL) | リンク | 閉じ) |

### 7.3 表示と保存

- 入力面では記号を残さず、変換後の見た目を表示する。

- 保存時はMarkdownへシリアライズし、再読み込み時に同じ見た目へ戻す。

- 貼り付けられたMarkdownも可能な範囲で変換する。プレーンテキスト貼り付け操作も提供する。

- 未対応のMarkdownは文字列として保持し、勝手に削除しない。

- コードブロック内では他のMarkdown変換を行わない。

## 8. 図生成・プレビュー

| 要素 | 仕様 |
| --- | --- |
| 主操作 | 『図を生成する』ボタン。Cmd/Ctrl + Enterのショートカット表示を添える。 |
| 生成中 | ボタンを一時無効化し、同時実行を防ぐ。前回図があれば残し、更新中表示を重ねる。 |
| 図ノード | 開始・終了は円、処理は角丸矩形、判断はひし形、戻りはループ矢印。 |
| 担当者 | 処理ノード上部に小さなラベルとして表示する。 |
| 警告 | 黄色系のバーとノードマーカー。断定的なエラーではなく『確認をおすすめします』と表現する。 |
| 元文章 | 警告またはノード選択時に、対応するメモ範囲をハイライトする。 |
| 保存状態 | 生成直後は『未保存の図』と表示し、自動保存しない。 |

## 9. HTML出力・ポンチ絵画面

### 9.1 画面構成

| 領域 | 内容 |
| --- | --- |
| 上部ツールバー | 閉じる、未保存/保存済み状態、ブラウザプレビュー、HTMLダウンロード、ポンチ絵を保存 |
| 中央プレビュー | タイトル、概要、アクティビティ図、分岐補足、関係者・判断・完了条件カード |
| 右設定パネル | レイアウト、タイトル、概要文、補足カード表示、アクセントカラー |

### 9.2 操作と保存の区別

| 操作 | 保存API | 画面上の結果 |
| --- | --- | --- |
| HTML出力を開く | 呼ばない | 現在データから未保存プレビューを作成 |
| 設定を変更する | 呼ばない | プレビューへ即時反映し、未保存状態を維持 |
| ブラウザプレビュー | 呼ばない | 別表示で完成イメージを確認 |
| HTMLをダウンロード | 呼ばない | 現在状態からファイルを生成 |
| ポンチ絵を保存 | 呼ぶ | 成功後に保存済み表示、保存時刻、スナップショットIDを更新 |

> **ボタン文言**  曖昧な『出力』や『完了』だけを使わず、『HTMLをダウンロード』『ポンチ絵を保存』のように結果を明記する。

### 9.3 未保存離脱

ポンチ絵のタイトル、概要、レイアウト、配色、補足表示を変更したあとに閉じようとした場合、以下の確認を表示する。HTMLダウンロード済みであっても保存済みとはみなさない。

> **確認ダイアログ**  このポンチ絵には未保存の変更があります。保存せずに閉じますか？　［編集に戻る］［保存して閉じる］［保存せず閉じる］

### 9.4 保存状態表示

| 状態 | 表示例 | 色 |
| --- | --- | --- |
| 未保存 | ● 未保存のポンチ絵 | Amber |
| 保存中 | 保存しています… | Neutral / spinner |
| 保存済み | ✓ 保存済み 10:42 | Green |
| 保存失敗 | 保存できませんでした　再試行 | Red |

## 13. アクセシビリティ

- すべてのボタンに視認できるラベルまたはaria-labelを付ける。

- パスワード入力には常時表示ラベル、エラーとの`aria-describedby`、表示切替ボタンの状態名を付ける。エラー時も入力欄へフォーカスを戻し、入力値を読み上げない。

- キーボードフォーカスを2px以上のアウトラインで明示する。

- 保存状態とエラーはaria-live領域で通知するが、入力中に過剰通知しない。

- ダイアログはフォーカストラップ、Escape、閉じた後のフォーカス復帰を実装する。

- 図の内容はnodes/edgesから生成したテキスト要約でも参照できる。

- 色だけで未保存・警告・エラーを区別せず、アイコンと文言を併用する。

- アニメーションはprefers-reduced-motionを尊重する。

## 15. デザイン受入チェック

| ID | 確認項目 |
| --- | --- |
| DS-AC-AUTH-01 | 未認証ではログイン画面だけが表示され、メモ本文や一覧が見えない。 |
| DS-AC-AUTH-02 | 正しいパスワードでログインでき、誤り・制限・設定不備は秘密情報を含まない共通文言で表示される。 |
| DS-AC-AUTH-03 | ログアウト後は保護画面へ戻れず、キーボードだけでもログイン・ログアウトできる。 |
| DS-AC-01 | Enterで改行され、図生成や保存が起動しない。 |
| DS-AC-02 | Cmd/Ctrl + Enterで図生成が1回だけ起動し、ショートカットがUIに表示される。 |
| DS-AC-03 | Tab/Shift + Tabでインデントが変化し、カーソルと選択範囲が自然に維持される。 |
| DS-AC-04 | Markdownショートカットが確定直後に視覚変換され、Undoで元に戻せる。 |
| DS-AC-05 | HTML出力、プレビュー、ダウンロードを行っても保存済み表示にならない。 |
| DS-AC-06 | ポンチ絵を保存したときだけ保存済み表示と保存時刻が出る。 |
| DS-AC-07 | 保存失敗時に未保存状態が維持され、内容が消えない。 |
| DS-AC-08 | マウスなしで主要フローを操作でき、フォーカス位置を見失わない。 |

## 16. 未決のデザイン事項

- メモ保存を完全手動にするか、復旧用のローカル下書きまたは自動保存を併用するか。

- Markdownのツールバーを常時表示するか、選択時のフローティング表示を併用するか。

- 図ノードをMVPから直接編集可能にするか、文章修正による再生成だけにするか。

- 保存済みポンチ絵を履歴として複数表示する場合の一覧UI。
