## 1. 文書の目的

本書は、FlowNoteのMVP開発で満たすべき業務要件、機能要件、非機能要件、データ要件および受入条件を定義する。実装方法の詳細は技術定義書、画面上の振る舞いはデザイン仕様書を正とする。

> **今回の確定事項**  ポンチ絵はHTML出力の実行だけでは保存しない。ユーザーが明示的に「保存」操作を行った場合にのみ保存する。

## 2. プロダクト概要

FlowNoteは、ユーザーが入力したメモを管理し、その内容からアクティビティ図を生成し、説明用のポンチ絵としてブラウザ表示・HTML出力できるメモアプリである。メモと保存済み図データはGoogle Sheets API経由で管理し、アプリケーションはNext.jsで実装してVercelへデプロイする。

### 2.1 目的

- 業務フローを文章で記録し、あとから検索・再編集できるようにする。

- 文章から処理、条件分岐、戻り、担当者、終了条件を抽出し、図として理解しやすくする。

- アクティビティ図を中心に、概要や判断ポイントを添えた一枚資料を作成する。

- 作業途中のプレビューと、明示的に保存された成果物を区別する。

### 2.2 対象ユーザー

MVPでは、業務手順、申請フロー、運用フローなどを整理する個人または小規模チームを対象とする。アプリ全体を1つの共有パスワードで保護し、認証済みセッションだけがメモとAPIを利用できることを前提とする。ユーザー別アカウントや個別パスワードはMVP対象外とする。

| 区分 | 対象 |
| --- | --- |
| MVP対象 | 共有パスワード認証、ログアウト、メモの作成・閲覧・編集・保存・削除、Markdown対応エディタ、Geminiによる構造化、アクティビティ図表示、ポンチ絵プレビュー、明示保存、単体HTML出力、Google Sheets保存、Vercelデプロイ |

| 将来候補 | Google OAuth、ユーザー別アカウント、図形の直接編集、版比較、コメント、共有リンク、PNG/SVG/PDF出力、データベース移行、組織単位の権限管理 |

## 4. 用語定義

| 用語 | 定義 |
| --- | --- |
| メモ | ユーザーがエディタで作成・管理する本文。Markdown表現を保持する。 |
| 図生成 | メモ本文を解析し、ノード・エッジ・警告からなるアクティビティ図データを作る処理。 |
| ポンチ絵 | アクティビティ図を主役に、タイトル、概要、関係者、判断ポイント、完了条件などを一枚に構成した説明資料。 |
| プレビュー | ブラウザ内に一時的に生成された未保存状態の図またはポンチ絵。 |
| 保存済みスナップショット | ユーザーが保存ボタンを押した時点の図データと表示設定。 |
| HTML出力 | 現在のプレビューから単体閲覧可能なHTMLファイルを生成・ダウンロードする処理。保存処理とは独立する。 |
| 共有パスワード | FlowNote全体へのアクセスを保護するMVP用の単一パスワード。平文は保存せず、環境変数のArgon2idハッシュと照合する。 |
| 認証セッション | パスワード照合成功後にサーバーが発行し、安全なCookieで保持する有効期限付きログイン状態。 |

## 5. 機能要件

### 5.1 パスワード認証

| 要件ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-AUTH-001 | Must | 未認証ユーザーにはログイン画面だけを表示し、メモ画面および保護対象APIへのアクセスを拒否する。 |
| FR-AUTH-002 | Must | 入力されたパスワードをサーバー側で`AUTH_PASSWORD_HASH`のArgon2idハッシュと照合する。平文パスワードを環境変数、Sheets、Cookie、ログへ保存しない。 |
| FR-AUTH-003 | Must | 認証成功時に有効期限付きセッションを発行し、HttpOnly、Secure（Production）、SameSiteを設定したCookieで保持する。 |
| FR-AUTH-004 | Must | ログアウトによりセッションCookieを無効化し、保護画面へ戻れないようにする。 |
| FR-AUTH-005 | Must | 認証失敗時はパスワードやハッシュの情報を含まない共通エラーを表示し、IP等を用いた試行回数制限と一時ロックを行う。 |
| FR-AUTH-006 | Must | ハッシュ未設定・形式不正の場合はFail Closedとし、アプリやAPIを利用可能にしない。 |
| FR-AUTH-007 | Should | セッション有効期限を環境変数で設定でき、期限切れ時はログイン画面へ戻す。 |

### 5.2 メモ管理

| 要件ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-NOTE-001 | Must | 新しいメモを作成できる。作成時に一意なIDを付与する。 |
| FR-NOTE-002 | Must | 保存済みメモの一覧を表示し、選択して本文を再表示できる。 |
| FR-NOTE-003 | Must | タイトルと本文を編集し、保存できる。未保存変更の有無を表示する。 |
| FR-NOTE-004 | Must | メモを論理削除できる。復元または完全削除はMVP後の拡張候補とする。 |
| FR-NOTE-005 | Should | タイトルまたは本文を対象に検索できる。 |
| FR-NOTE-006 | Should | 更新競合を検出し、他の更新を無言で上書きしない。 |

### 5.3 メモエディタ

| 要件ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-EDIT-001 | Must | Enterキーは常に改行を行い、図生成・保存・送信処理を実行しない。 |
| FR-EDIT-002 | Must | macOSではCmd + Enterで図生成を実行する。Windows/Linux向けにCtrl + Enterも同等操作として提供する。 |
| FR-EDIT-003 | Must | Tabキーはエディタ内でインデントを1段深くする。Shift + Tabは1段浅くする。 |
| FR-EDIT-004 | Must | 選択範囲が複数行の場合、Tab/Shift + Tabを対象行全体へ適用する。 |
| FR-EDIT-005 | Must | Markdownショートカットを認識し、コマンド確定直後に入力面へ視覚反映する。 |
| FR-EDIT-006 | Must | Markdownへの変換後も、Markdownテキストとして保存・復元できる。 |
| FR-EDIT-007 | Should | ツールバーとキーボード操作の双方から同じ書式を適用できる。 |
| FR-EDIT-008 | Must | IME変換確定中のEnterを改行や図生成として誤処理しない。 |

### 5.4 Markdownショートカット

| 入力 | 確定操作 | 即時反映 |
| --- | --- | --- |
| # / ## / ### + 半角スペース | スペース入力 | 見出し1 / 2 / 3 |
| - または * + 半角スペース | スペース入力 | 箇条書き |
| 1. + 半角スペース | スペース入力 | 番号付きリスト |
| > + 半角スペース | スペース入力 | 引用 |
| ``` | 3つ目のバッククォート入力 | コードブロック |
| **text** / *text* / ~~text~~ / `text` | 閉じ記号入力 | 太字 / 斜体 / 取り消し線 / インラインコード |

> **入力原則**  Slackの入力画面と同様に、入力した記法は確定後すぐ視覚表現へ変換する。ただし保存時の正本は再生成可能なMarkdown文字列とし、変換で情報を失わない。

### 5.5 図生成・確認

| 要件ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-DIAG-001 | Must | 図生成ボタンまたはCmd/Ctrl + Enterにより、現在のメモ本文から図データを生成する。 |
| FR-DIAG-002 | Must | Geminiの出力を定義済みJSON Schemaへ制約し、アプリ側で整合性検証する。 |
| FR-DIAG-003 | Must | 処理、条件分岐、分岐ラベル、戻り、担当者、開始、終了を表現できる。 |
| FR-DIAG-004 | Must | 曖昧・不足・矛盾がある箇所を警告として表示し、推測した事実として確定しない。 |
| FR-DIAG-005 | Must | 図生成直後のデータは未保存状態とし、メモまたは図の保存を自動実行しない。 |
| FR-DIAG-006 | Should | 元文章とノードの対応箇所を追跡できる。 |

### 5.6 ポンチ絵・HTML出力・保存

| 要件ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-OUT-001 | Must | HTML出力画面を開くと、現在の図からポンチ絵プレビューを一時生成する。 |
| FR-OUT-002 | Must | HTML出力画面を開く、プレビューする、HTMLをダウンロードする操作では保存を行わない。 |
| FR-OUT-003 | Must | 「ポンチ絵を保存」ボタンを押した場合にのみ、図データと出力設定を保存する。 |
| FR-OUT-004 | Must | 未保存のポンチ絵には未保存表示を出し、画面を閉じる際は必要に応じて確認する。 |
| FR-OUT-005 | Must | HTMLは外部ライブラリや外部画像なしでも単体で閲覧できる。 |
| FR-OUT-006 | Must | 保存済みポンチ絵を再表示し、同じ設定からHTMLを再出力できる。 |
| FR-OUT-007 | Should | レイアウト、概要文、補足カード、アクセントカラーを出力前に調整できる。 |
| FR-OUT-008 | Must | 保存対象は図の構造データと表示設定であり、生成済みHTML本文の保存はMVPでは行わない。 |

### 5.7 データ保存

| 要件ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-DATA-001 | Must | Next.jsサーバーからGoogle Sheets APIを呼び出してデータを読み書きする。ブラウザから直接呼び出さない。 |
| FR-DATA-002 | Must | メモ本文、図データ、警告、保存済みポンチ絵設定、作成・更新日時、版番号を管理する。 |
| FR-DATA-003 | Must | シートの行番号ではなくUUIDをレコード識別子として使用する。 |
| FR-DATA-004 | Must | APIエラー時に保存成功と表示せず、再試行可能な状態を維持する。 |

## 6. 非機能要件

| 分類 | 要件 |
| --- | --- |
| セキュリティ | パスワードはArgon2idハッシュだけをサーバー環境変数へ保存する。Gemini APIキーとGoogleサービスアカウント秘密鍵もサーバー環境変数として保持し、いずれもブラウザへ送信しない。ログインとAPIにレート制限を設ける。 |
| 性能 | 一般的な数千文字程度のメモは、保存操作を2秒以内、AI図生成を原則10秒以内に結果または進捗表示へ遷移させる。 |
| 信頼性 | 保存は冪等性を考慮し、二重クリックによる重複行を防ぐ。外部API障害時は入力内容を画面上に保持する。 |
| 可用性 | VercelのProduction/Preview環境を分離し、環境変数変更後は再デプロイで反映する。 |
| アクセシビリティ | 主要機能をキーボードで操作でき、フォーカス状態、ラベル、エラー内容を支援技術へ伝える。 |
| 互換性 | 最新2世代のChrome、Safari、Edgeを主要対象とし、レスポンシブ表示へ対応する。 |
| 保守性 | AIモデル名、シートID、対象レンジ、文字数上限をコード変更なしで設定可能にする。 |
| 監査性 | 保存・図生成・保存失敗を追跡できるログを残す。本文や秘密情報はログへ出さない。 |

## 8. 主要受入条件

| ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-AUTH-01 | 未認証である | メモ画面または保護APIへアクセスする | ログイン画面または401へ遷移し、データを返さない |
| AC-AUTH-02 | 正しい共有パスワードを入力済み | ログインする | セッションが発行され、メモ画面を表示する |
| AC-AUTH-03 | 誤ったパスワードを入力済み | ログインする | 共通エラーを表示し、セッションを発行しない |
| AC-AUTH-04 | ログイン済みである | ログアウトする | セッションが無効化され、保護画面へ再アクセスできない |
| AC-AUTH-05 | ログイン失敗を短時間に繰り返す | 制限回数を超える | 429または同等の一時制限となり、成功・失敗理由の詳細を漏らさない |
| AC-EDIT-01 | メモエディタにフォーカスがある | Enterを押す | 改行され、図生成や保存は実行されない |
| AC-EDIT-02 | 本文が入力済み | Cmd + Enterを押す | 図生成が1回だけ開始される |
| AC-EDIT-03 | 行頭に「- 」を入力する | スペースを確定する | 箇条書き表示へ即座に変換される |
| AC-EDIT-04 | 複数行を選択している | Tabを押す | 選択行が1段インデントされ、フォーカスはエディタ内に残る |
| AC-OUT-01 | ポンチ絵が未保存 | HTML出力画面を開く | プレビューのみ生成され、保存APIは呼ばれない |
| AC-OUT-02 | ポンチ絵が未保存 | HTMLをダウンロードする | ファイルは生成されるが保存APIは呼ばれない |
| AC-OUT-03 | ポンチ絵が未保存 | 「ポンチ絵を保存」を押す | 保存成功後に保存済み表示と保存時刻が出る |
| AC-DATA-01 | 保存APIが失敗する | ユーザーが保存する | 失敗を表示し、編集中の内容と未保存状態が維持される |

## 9. 未決事項・確認事項

> **要確認**  以下は実装開始前にプロダクト判断が必要である。未決のままの場合は技術定義書に記載した推奨案を暫定採用する。

- 共有パスワード方式をユーザー別アカウントへ移行する時期。MVPは単一パスワード・単一論理所有者として扱う。

- メモ本文の保存を明示保存だけにするか、一定時間後の自動保存も併用するか。推奨は明示保存＋復旧用ローカル下書き。

- 保存済みポンチ絵を複数版保持するか、最新版だけを保持するか。推奨はスナップショット方式。

- Google Sheetsのデータ件数が増えた際のデータベース移行条件。推奨は数千件または同時更新要件発生時に再評価。

- AIによる分析対象へ機密情報を入力できる運用にするか、および利用規約・保持方針。

## 10. 完了条件

- Must要件と主要受入条件が自動テストまたは受入テストで確認されている。

- Production環境の秘密情報がVercelの環境変数へ登録され、クライアントバンドルへ含まれていない。

- `AUTH_PASSWORD_HASH`に平文ではなくArgon2idのエンコード済みハッシュを設定し、正常・失敗・レート制限・ログアウトを確認できる。

- Google Sheetsへの作成・取得・更新と、Geminiによる構造化出力が本番相当環境で確認されている。

- HTML出力とポンチ絵保存が明確に分離されている。
